# textlint の利用手順

textlint を文章の候補箇所を見つける補助として使う。検出結果から著者が AI かどうかを判定しない。

## 既存環境で実行する

1. 対象プロジェクトの `package.json`、lockfile、textlint 設定、除外設定を読む。設定形式とパッケージマネージャーは既存のものに合わせる。
2. 既存の文書 lint コマンドを優先する。対象ファイルを渡せる場合は変更した文書に限定する。コマンドの実際の引数仕様を確認する。
3. ローカルに textlint が導入されている場合、プロジェクトルートから次のように実行できる。ファイル名は実際の対象に置き換える。

```sh
./node_modules/.bin/textlint "docs/setup.md"
```

実行ファイルや依存関係がなければ、検査未実施として目視確認を続ける。単なる文章編集のために `npx` で未導入パッケージを取得したり、lockfile を更新したりしない。

## 導入も依頼された場合

npm を使うプロジェクトでは、プロジェクトルートで次を実行する。他のパッケージマネージャーではその慣例に合わせる。

```sh
npm install --save-dev textlint textlint-rule-preset-ai-words-ja
```

既存の設定を保持し、次のルールをマージする。設定がなければ `.textlintrc.json` を作る。

```json
{
  "rules": {
    "preset-ai-words-ja": true
  }
}
```

導入したバージョンと lockfile を確認し、実際の文書で実行する。文章編集だけで hooks や CI を追加せず、自動検査の導入まで依頼された場合に既存の運用へ組み込む。

## 指摘への対応

指摘された文を前後と一緒に読み、対象・操作・結果が不明なら具体化する。文脈に合う用語は残す。ルールを通すために意味を変えたり、引用を書き換えたりしない。

反復して使う正当な用語をプロジェクト全体で許可する必要がある場合は、設定変更の依頼範囲を確認し、`allows` に理由のある語だけを追加する。次は製造分野の文書を想定した例であり、すべてのプロジェクトに適用しない。

```json
{
  "rules": {
    "preset-ai-words-ja": {
      "no-ai-words": {
        "allows": ["部品", "検査"]
      }
    }
  }
}
```

引用など一箇所だけの例外を全体の許可語にしない。既存の局所抑制の仕組みがある場合はその規約に従う。設定変更が範囲外なら、本文を維持して残る指摘と理由を報告する。

修正後に再実行し、終了コードと残る指摘を確認する。設定読み込み失敗や依存関係不足を、文章への指摘と区別する。未実行、実行失敗、指摘あり、指摘なしを混同しない。

## 仕様の確認先

設定例は 2026-09-18 に確認した資料に基づく。導入バージョンで利用可能な設定を確認し、検出語の固定リストをスキル内に複製しない。

- [紹介記事](https://blog.p1ass.com/posts/textlint-rule-preset-ai-words-ja/) — 導入の背景と使用例。
- [公式リポジトリ](https://github.com/p1ass/textlint-rule-preset-ai-words-ja) — オプションと検出対象。`no-ai-words` は形態素に基づく検出を行う。
