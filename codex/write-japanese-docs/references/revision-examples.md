# 意味を保つ推敲例

以下はこのスキルのために作成した例であり、参考資料からの引用ではない。修正文の事実が資料で確認できる場合にのみ採用する。例文の数値や条件を実際の文書に流用しない。

## 操作と結果を明らかにする

修正前:

> この機能は文書管理を飛躍的に進化させる強力な基盤です。

資料で確認できた機能が「文書ごとに承認者を設定できる」なら、次のように書く。

> 文書ごとに承認者を設定できます。

根拠のない評価語を別の評価語に置換せず、確認できる動作を書く。具体的な効果まで資料になければ、所要時間の削減などを付け足さない。

## 不確実性と条件を残す

修正前:

> ログを見る限り、同時更新が原因かもしれないと考えられます。

修正後:

> ログからは、同時更新が原因の可能性があります。

調査中であれば「同時更新が原因です」に変えない。追加で調べる対象が分かっている場合は、その確認方法を続ける。

仕様が「最長 24 時間以内の再送に限って重複を除外する」なら、「重複を防ぎます」と短縮せず、期間の条件を残す。

## 手順を再現できるようにする

修正前:

> 適切に設定してから実行し、問題がないことを確認します。

設定ファイル、実行コマンド、期待結果が確認できた場合は、次の情報を順に書く。

1. 編集するファイルと設定項目、値の選び方。
2. コマンドを実行するディレクトリとコマンド。
3. 成功時に確認する表示や生成ファイル。
4. 想定する失敗と対処方法。

未確認のコマンドを補完して実行例にしない。文法を説明するコードと、そのまま実行できるコードを区別する。

## 語彙チェックを文脈で判断する

| 文 | 判断 |
| --- | --- |
| 「この施策が効きます」 | 何がどう変わるかを資料から確かめ、効果を具体的に書く。 |
| 「検査工程で部品の寸法を測定する」 | 製造の文書なら対象と操作が明確なので維持する。 |
| 「照合 API の `match_id` を指定する」 | 正式名称と識別子なら維持する。 |
| 「重要な課題を包括的に解決します」 | 解決する課題と対応範囲を明記する。分からなければ断言を削る。 |

検出語を別の曖昧な語に変えても、説明の不足は解消しない。元の語を残すほうが正確なら残す。

## 文章中に残った英語を整える

日本語化する対象は説明の表記であり、実装の名前ではない。同じ英単語でも使い方ごとに判断する。

修正後の列には完成した例文だけを置く。変更が不要な例は修正前と同じ文を示し、その理由を判断理由の列に記す。

| 修正前 | 修正後 | 判断理由 |
| --- | --- | --- |
| session の終了後に resource を解放する。 | セッションの終了後にリソースを解放する。 | プログラミング分野で自然なカタカナ表記にする。 |
| public header に library の型を公開する。 | 公開ヘッダーにライブラリの型を公開する。 | 定着した訳語とカタカナ表記を使う。 |
| retry の条件を config に記述する。 | 再試行の条件を設定に記述する。 | 一般概念を表す語なので日本語にする。 |
| native lowering を backend が担当する。 | ネイティブ実行単位への変換をバックエンドが担当する。 | この文脈で lowering が実行単位への変換を意味すると確認できた場合の例。 |
| plan/session の consumer を切り替える。 | 計画とセッションを利用する側を切り替える。 | 複合語が表す関係を文として説明する。 |
| `session_id` を渡して HTTP API を呼び出す。 | `session_id` を渡して HTTP API を呼び出す。 | 識別子と定着した略語なので変更しない。 |
| `--retry` を指定して再試行する。 | `--retry` を指定して再試行する。 | オプション名は正確に残し、説明も既に日本語なので変更しない。 |

これらの訳は文脈に応じた例であり、固定の置換辞書として使わない。プログラミングの説明では `resource` は原則として「リソース」とし、定着したカタカナ語を無理に漢語へ置き換えない。既存の用語集や対象分野で別の表記が定着している場合はそれに従う。ただし、文書内に英語が混在しているという理由だけで未推敲の表記を踏襲しない。

原語による検索や実装との対応付けが必要なら、初出を「実行受入判定（admission）」のように示す。全出現箇所に英語を併記せず、その後は選んだ日本語表記で統一する。定着した訳語がなく原語を残す場合も、読者が意味を理解できる説明を添える。

英字検索にはコード、URL、パスも含まれるため、候補ごとに役割を確かめる。リンクの表示名は説明として推敲できるが、リンク先のファイル名は翻訳しない。見出しを変えた場合は参照元のアンカーを更新する。コードブロック中の実行コード、文字列リテラル、引用した出力を文章の表記統一に巻き込まない。

この確認観点は、ユーザーが提示した [Adaptive-Execution-Residency の推敲コミット](https://github.com/tappei335/Adaptive-Execution-Residency/commit/616aa555087c12e2e594b4435b804ddc5be3d26f) を参考に追加した。上記の例文は判断基準を示すために作成した。
